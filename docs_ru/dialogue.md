# Диалоги, дневник и UI карты мира

Как устроены три «читательских» UI игры. У них общий слой данных (база
строк + скриптовые UI-формы), но каждый имеет свой собственный класс
override-контекста.

- **Диалог**: `CUIDialogContext` —
  `Game/Game/UIDialogContext.{cpp,h}`. UI-форма: `UI.vfs/dialog.xml`.
  Фабрика override'ов: `Game/Game/DialogOverride.{cpp,h}`.
  Логика разговора: `Game/Game/Conversation.{cpp,h}`.
- **Дневник** (журнал игрока): `CUIDiaryContext` —
  `UIDiaryContext.{cpp,h}`. UI-форма: `UI.vfs/diary.xml`.
  Override: `DiaryOverride.{cpp,h}`. Данные: `Diary.{cpp,h}`.
- **Карта мира**: `CUIMapContext` — `UIMapContext.{cpp,h}`.
  UI-форма: `UI.vfs/worldmap.xml`. Override:
  `MapOverride.{cpp,h}`. Битмап карты + попиксельный pick:
  [`formats/map.md`](formats/map.md). Метки: `WorldMap.cpp` (см.
  `CWorldMap::CMark`, `IWorldMapMark`).

---

## 1. Стек override'ов

UI-контексты помещаются в **очередь override'ов**
(`IOverrideQueue` — `Game/Game/IOverrideQueue.h`). Каждый override:

- Приостанавливает симуляцию мира (или нет — `WorldStopOverride.cpp`
  это контролирует).
- Переключает фокус ввода на свой собственный UI-скрипт.
- При закрытии выталкивает себя и возобновляет нижележащее состояние.

Классы override'ов (`Game/Game/*Override.cpp`):

| Класс                          | Что он переопределяет                                            |
|--------------------------------|------------------------------------------------------------------|
| `CDialogOverride`              | Экран диалога с NPC                                              |
| `CDiaryOverride`               | Дневник игрока                                                   |
| `CMapOverride`                 | Карта мира                                                       |
| `CInventoryOverride`           | UI инвентаря                                                     |
| `CTradeOverride`               | Торговля с NPC                                                   |
| `CChooseItemOverride`          | Подсказка выбора предмета                                        |
| `CPlayerStatOverride`          | Экран статов / детальный HUD                                     |
| `CMessageOverride`             | Однострочное всплывающее сообщение                               |
| `CGameMenuOverride`            | Меню паузы / настроек                                            |
| `CGameOverOverride`            | Экран смерти                                                     |
| `CInitGameOverride`            | Выбор персонажа в новой игре                                     |
| `CInitMovieOverride`           | Вступительный ролик                                              |
| `CInGameMovieOverride`         | Кинематографическая вставка                                      |
| `CMovieOverride`               | Общее воспроизведение ролика                                     |
| `COverrideFactoryPlayMovie`    | Фабрика, создающая `CMovieOverride` по запросу                   |
| `CSleepLoopOverride`           | Цикл «спать до…»                                                 |
| `CWorldStopOverride`           | Приостанавливает обновление мира без показа UI                    |
| `CWindowOverride`              | Общее окно (родительский класс для некоторых из перечисленных)    |

## 2. Диалог

### 2.1 Запуск

Скрипты инициируют разговор вызовом host-API (см.
[script_api.md](script_api.md)) вида
`@StartConversation(npc, dialogue_id)`. Движок помещает
`CDialogOverride` в стек override'ов и создаёт
`CConversation` с данными «дерева» диалога.

### 2.2 Данные разговора

`CConversation` содержит:

- **Текущий узел** (вопрос + список ответов игрока).
- Полный **граф узлов** (загружен из привязанного скрипта диалога и
  базы строк).
- **Условия** для каждого узла (скриптовые флаги / переменные,
  которые должны выполняться).
- **Побочные эффекты** для каждого ответа (дать предмет, изменить
  репутацию, установить флаг).

Каждый узел разговора имеет целочисленный ID, ссылающийся на
`Strings.vfs/main.dat` (`formats/dat_strings.md`). Голосовая реплика NPC
в этом узле — это поиск по ID строки; аудио лежит в
`Sounds.vfs` ([`formats/ogg.md`](formats/ogg.md)) под именем,
соответствующим конвенции ID строки.

### 2.3 Привязка к UI

Форма `dialog.xml` (`UI.vfs/dialog.xml`) задаёт визуальный лэйаут:
портрет NPC, прокручиваемая область текста, кнопки ответов. Её
привязанный скрипт (`Scripts.vfs/ui_dialog.bin`) получает состояние
узла с C++-стороны через `CUIDialogContext` и отрисовывает соответствующе.

Когда игрок выбирает ответ, скрипт отправляет скриптовое событие
обратно в объект разговора, который продвигает граф и
запускает любые побочные эффекты (вероятно, через `RunScript("dialog_…")`).

## 3. Дневник

Дневник — это **персистентный журнал игрока**: открытые записи,
заметки о персонажах, сводки квестов.

- `CDiary` (`Diary.cpp`) содержит упорядоченный список `CDiaryEntry`.
- Каждая запись: ID строки заголовка, ID строки тела, дата, персонаж,
  к которому она относится, **флаг прочтения**.
- `AddEntry(stringID, …)` вызывается из скриптов при разблокировке
  новой записи; UI затем показывает уведомление «новая запись».

Формат сохранения: `CDiary::SaveObject` пишет записи напрямую в
поток сохранения ([save_format.md](save_format.md)). ID строк
интернируются системой сохранения, так что дневник на тысячу записей
не раздувает сохранение.

UI-форма: `UI.vfs/diary.xml` + скрипт `ui_diary.bin`. Скрипт
запрашивает у `CDiary` количество записей, заполняет элементы списка,
обрабатывает прокрутку.

## 4. Карта мира

UI карты мира использует три источника данных вместе:

1. **Фоновый битмап** — нарисованная карта города, хранится как `.tex`
   или `.tga` в `Textures.vfs`. Загружается опосредованно через
   [`formats/map.md`](formats/map.md).
2. **Сетка регионов** — полигональное разбиение из префикса PlaneGrid
   того же файла `.map`. Используется для подписей регионов и
   подсветки.
3. **Попиксельная сетка объектов** — 16-битные индексы в массив
   OBJECT_DATA, также из `.map`. Разрешает клик мыши в id объекта
   за O(1).

`CWorldMap::CMark` (`WorldMap.cpp:405`) представляет **метку**: булавку,
помещённую на карту игроком или скриптом. Каждая метка имеет
позицию (в пикселях текстуры карты), цвет, ID строки подсказки и
ассоциированное мировое местоположение (так что запросы «найти
путь к этой метке» могут запускать поиск пути).

UI-форма: `UI.vfs/worldmap.xml` + скрипт `ui_worldmap.bin`. Скрипт
обрабатывает панораму/зум, расстановку меток и поток ответа
«быстрое перемещение» (который сам по себе — ещё один push override'а
при подтверждении).
