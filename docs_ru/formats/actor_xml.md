# Actor `.xml` — конфигурация «Extras» для экземпляра

- **Архив**: `Actors.vfs` (484 файла).
- **Примеры**: `agony_common.xml`, `blood.xml`, `torch.xml`,
  `sound_river.xml`, `named.xml`, `indoor_door.xml`.
- **Парсер**: `CSimpleXML` (`IXMLParser`) в
  `Game/Engine/SimpleXML.cpp`.
- **Потребитель**: `CCreateParamsActor`
  (`Game/Engine/CreateParamsActor.cpp`) — оборачивает распарсенный XML в
  интерфейс `ICreateParams`, который потребляет каждый конструктор актора.
- **Связывание**: на файл ссылаются из [`.isc`](isc.md) / [`.osc`](osc.md) через
  `<Actor Name="..." Extras="filename.xml"/>`.

---

## 1. Назначение

Actor XML предоставляют **переопределения для экземпляра** поверх бинарных
данных актора ([actor_placement.md](actor_placement.md)). Бинарный файл
описывает, «что это за актор» (меш, коллизия, идентификатор типа); XML
описывает, «как ведёт себя именно это размещение» — его скрипт, его
инвентарь, его список звуков, его скриптируемые свойства.

Многие мелкие варианты используют один и тот же бинарный файл размещения и
отличаются только своим XML — например, любой актор-дверь использует один из
нескольких базовых XML (`indoor_door.xml`, `outdoor_door.xml`) и
переопределяет один-два атрибута.

---

## 2. Корневой элемент: `<Extras>`

Каждый файл обёрнут в единственный корень `<Extras>`. Наименьший допустимый
файл, таким образом:

```xml
<Extras>
</Extras>
```

(`Actors.vfs/agony_common.xml`, 21 байт — заглушка для
актора, которому ничего не нужно на уровне экземпляра.)

XML парсится `CSceneIndoor::CreateActor` /
`CSceneOutdoor::CreateActor`, которые вызывают
`pParser->FindNodePtr(NULL, "Extras")` и передают этот узел в
`CCreateParamsActor`. С этого момента всё — поиск по имени в узле
`Extras` и его потомках.

---

## 3. Распознаваемые потомки `<Extras>`

### 3.1 `<ID>name</ID>`

Необязательно. Переопределяет имя поиска, используемое для регистрации актора
в `CWorld`. Если пусто, используется имя актора из родительского
`<Actor Name="…">`. Используется, чтобы несколько сцен могли ссылаться на
один и тот же актор по стабильному имени.

### 3.2 `<Script>name.bin</Script>`

Ссылка на скомпилированный скрипт (в `Scripts.vfs`, см. [bin.md](bin.md)),
управляющий логикой этого актора. Скрипт запускается при создании актора;
его задача `init()` получает актор как `this`.

### 3.3 `<Properties>…</Properties>`

Именованные переменные экземпляра, доступные привязанному скрипту. Каждый
потомок — одно свойство; имя тега — это имя свойства. Необязательный
атрибут `type` выбирает тип хранения значения:

```xml
<Properties>
    <reference_distance type="float">1000</reference_distance>
    <sound_distance     type="float">3000</sound_distance>
    <num_sounds         type="int">1</num_sounds>
    <night>1</night>                       <!-- default type = string -->
</Properties>
```

Распознаваемые значения `type`: `int`, `float`, `string` (по умолчанию).

Свойства предоставляются привязанному скрипту как глобальные переменные (см.
`Properties` и `HasProperty` в [`script_api.md`](../script_api.md)).

### 3.4 `<Items>…</Items>`

Начальное содержимое инвентаря — по одному потомку на тип предмета, например
`<peanut amount="3"/>`. Разрешается по глобальной базе предметов в
[world_xml.md](world_xml.md). Загрузку выполняет `AddInvItemsFromParams`;
см. `Game/Game/InvItemContainer.cpp`.

### 3.5 `<Sounds>…</Sounds>`

Именованные алиасы звуков. Каждый потомок сопоставляет видимый скрипту
алиас с именем файла `.ogg`:

```xml
<Sounds>
    <sound01>River.ogg</sound01>
</Sounds>
```

Скрипты затем вызывают `PlaySound(self, "sound01")` и т. п. Список звуков
загружает `LoadSoundList(ISoundManager *, ICreateParams *)`
(`Game/Game/SoundList.cpp`).

### 3.6 `<Particlesystems>…</Particlesystems>` (также `<particlesystems>`)

Эффекты частиц, которые может спавнить актор. Каждый потомок — одна
именованная система с фиксированной схемой:

```xml
<particlesystems>
    <torch>
        <texture>fire.tex</texture>
        <maxparticles>40</maxparticles>
        <lifetime>1.00</lifetime>
        <texx>2</texx>
        <texy>2</texy>
        <data>1.00;0.00;…</data>          <!-- 60 semicolon-separated floats -->
    </torch>
</particlesystems>
```

Элемент `<data>` — плоский список разделённых `;` чисел с плавающей точкой —
ровно **54 значения** (9 каналов × 6 чисел каждое: avg, disp, speedAvg,
speedDisp, accelAvg, accelDisp) для блока параметров системы частиц. Каналы в
порядке: Red, Green, Blue, Alpha, Size, Angle, Gravity, Viscosity, Frame.
Парсится `CActorScripted::_PSInitFromString`
(`Game/Game/ActorScripted.cpp:810`). См.
[particle_system.md](../particle_system.md) для полной схемы.
Лишние конечные токены (некоторые файлы содержат 60 разделителей с пустыми
завершающими полями) молча игнорируются.

### 3.7 Флаги

Потомки, представляющие собой одиночные слова, действуют как булевы флаги.
Распознаваемые:

| Тег                | Эффект                                                  |
|--------------------|---------------------------------------------------------|
| `<usable/>`        | Актор может быть активирован игроком (клавиша `E`).     |
| `<Collectable/>`   | Актор — подбираемый предмет инвентаря.                  |
| `<keep/>`          | Сохраняется при выгрузке сцены (принудительно).         |
| `<nokeep/>`        | Принудительно удаляется при выгрузке (отменяет умный сбор мусора). |

Важно само наличие тега; его содержимое значения не имеет.

### 3.8 `<ContainerCapacity>N</ContainerCapacity>`

Вместимость инвентаря для контейнерных акторов. По умолчанию
`CONTAINER_CAPACITY` (определена в `Config.h`), если пропущено.

### 3.9 `<Group id="N"/>`

То же, что и в [isc.md](isc.md) — привязывает актор к скриптовой группе.
Чаще всего присутствует в `<Actor>` внутри XML сцены, но допустимо и
здесь.

## 4. Авто-инжектируемые параметры

`CCreateParamsActor` добавляет два синтетических параметра, **не**
присутствующих на диске, но видимых конструктору актора:

- `#SourceXML` — имя XML-файла, из которого пришёл этот Extras (используется
  для диагностики: `m_strXMLName` логируется, если с актором что-то не так).
- `#Actor` — указатель на родительский актор (для вложенных параметров).

Ведущий `#` обозначает «внутренние» параметры, которые скрипты не могут
переопределить.
