# `.bump` — текстура bump-карты

- **Архив**: `Textures.vfs` (1 файл: `boini_sh_254.bump`, 786 450 байт).
- **Загрузчик**: тот же путь `CTexturePlain::CTexturePlain(...)`, что и для
  [`.tex`](tex.md), достигаемый через
  `CRenderer::TextureCreate(strBumpName)` из одной из техник
  bump-маппинга (`TechniqueDiffuseBump.cpp:31`, `TDDiffuseBump.cpp:36`,
  `TechniqueDiffuseBumpNB.h:33`).

---

## 1. Формат: фактически это TGA

`Textures.vfs/boini_sh_254.bump` — **стандартный 24-битный несжатый
TGA-файл** с изменённым расширением. Эмпирический 18-байтовый заголовок
(проверен hex-дампом):

```
00 00 02 00 00 00 00 00 00 00 00 00 00 02 00 02 18 00
└──┴─ ─┘└── ColorMap (5 bytes) ──┘└─ Image origin (4)┘└W ┘└H ┘└Bp ┘└Imd┘
 │  │     all zero                 0,0                512  512  24  0
 │  └── ImageType = 2 (uncompressed truecolor)
 └── ID length = 0
```

Width 0x0200 = 512, height 0x0200 = 512, bpp 24, без image descriptor.

Полезная нагрузка: `512 × 512 × 3 = 786432` байт пиксельных данных BGR.
Заголовок 18 + payload 786432 = **786 450 байт** ровно — совпадает с
размером файла.

Соглашение об именовании — это подсказка для человека (и для конвейера
сборки): ресурс предназначен для привязки как **bump-текстура**, а не как
диффузная карта. Сам движок не отличает формат — он вызывает
`D3DXCreateTextureFromFileInMemoryEx` и получает RGB-текстуру 512×512
независимо от расширения.

---

## 2. Как движок использует это

Каждая техника рендера bump-маппинга объявляет дескриптор экземпляра с
двумя именами текстур — diffuse + bump — и использует bump-текстуру как
**карту нормалей**, сэмплируемую в слоте 1
(`TechBaseDiffuseBump.cpp:63, :95, :144`):

```cpp
pRenderer->TextureSet(GetBumpTexture(), 1);
```

Пиксельный шейдер ожидает значения RGB в [0, 255], кодирующие вектор
нормали `(nx, ny, nz)` после типичного декодирования `2 × T − 1`.
Единственный поставляемый `.bump` (`boini_sh_254.bump`) — карта нормалей
512×512, парная с конкретной стационарной diffuse-текстурой в
`boini_sh_254*`.

---

## 3. Сжатие

**Нет.** Несжатый 24-битный TGA. Ни обёртки `%ZIP`, ни DXT.

---

## 4. Зачем отдельное расширение?

Три причины, в порядке важности:

1. **Дисциплина авторинга**: художники знают, что `.bump`-файлы требуют
   плоского, тайлящегося содержимого карты нормалей, а не диффузной живописи.
2. **Поиск в конвейере сборки**: запекальщик ресурсов может применять
   разные настройки цветового пространства или режима DXT в зависимости от
   расширения (DXT5n vs DXT1), когда позже конвертирует их в `.tex`.
3. **Никакой тихой путаницы** с одноимённой диффузной `.tex` рядом.

Альфа-сборка содержит только один экземпляр `.bump` — большинство
поверхностей вместо этого используют DXT5n внутри `.tex`. Расширение — это
рудимент более раннего рабочего процесса с ресурсами.
