# `.hand` — меш руки / руки от первого лица

- **Архив**: `Geometries.vfs` (1 файл: `danko.hand`).
- **Загрузчик**: `CHandsData::CHandsData(...)` и `CHandsDesc` —
  `Game/Game/HandsData.cpp` и `Game/Game/HandsDesc.cpp`.
- **Владеющие интерфейсы**: `IHandsData`, `IHandsDesc`.

---

## 1. Назначение

Единственная модель «рук» от первого лица, используемая для рендеринга рук
игрока, держащих оружие. Единственный персонаж, у которого вообще есть вид
от первого лица, — это **Данко** (Бакалавр), поэтому поставляется только
один `.hand`.

Функционально это тонкая специализация [`.mesh`](mesh.md): та же
философия вершинных потоков, но с **именованными костями** и
**покадровыми треками анимации**, поскольку камера жёстко прикреплена к
модели руки, и любое видимое дрожание очевидно.

---

## 2. Раскладка на диске

Загрузчик небольшой. Из `HandsData.cpp` структура:

```
+--------------------------+
| u32  nVertices           |
| VERTEX[nVertices]        |   20 bytes each (pos.xyz + uv.xy) — same as .mesh
+--------------------------+
| u32  nFaces              |
| u16  indices[nFaces * 3] |
+--------------------------+
| CEString textureName     |
+--------------------------+
| u32  nBones              |
| BONE[nBones]             |   per-bone weight tables (see 2.1)
+--------------------------+
| u32  nAttachments        |
| ATTACH[nAttachments]     |   weapon-grip locators (see 2.2)
+--------------------------+
| u32  nAnimations         |
| ANIMATION[nAnimations]   |   per-track keyframes (see 2.3)
+--------------------------+
```

### 2.1 `BONE`

```
CEString name                   // например, "thumb_tip_l", "wrist_r"
CVector  pivot                  // 12 байт, опорная точка в локальном пространстве
u32      nVertices              // вершин, скиннящихся к этой кости
u32[]    vertexIndices          // индексы в VERTEX[]
```

### 2.2 `ATTACH`

```
CEString name                   // "grip_main", "grip_off"
u32      boneIndex              // родительская кость для захвата
CVector  position               // локальное смещение
CVector  direction              // ось «вперёд» (единичная)
```

Эти локаторы — точки, к которым во время выполнения родительски привязываются
меши оружия (`HandsDesc.cpp` вызывает `Attach()`).

### 2.3 `ANIMATION`

```
CEString name                   // "idle", "fire", "reload", "switch"
f32      duration                // секунды
u32      nKeyframes
KEYFRAME[nKeyframes]
```

Каждый `KEYFRAME`:

```
f32          time                 // секунды с начала трека
u32          nBoneXforms
BONE_XFORM[nBoneXforms]
```

Каждый `BONE_XFORM`:

```
u32   boneIndex
CQuat rotation                    // 16 байт (x, y, z, w)
CVector translation               // 12 байт
```

Рендер выполняет LERP-смешивание между соседними ключевыми кадрами;
повороты используют slerp по короткой дуге через `CQuat::Slerp`.

---

## 3. Сжатие

Не сжато. Загружается как memory-mapped бинарный блоб через тот же путь
`IMMLoadObject`, что и `.mesh`.

---

## 4. Связь с другими форматами

- Меш руки независим от [`.lsh`](lsh.md). У лиц и рук отдельные риги.
- Меши оружия, прикрепляемые к локаторам `ATTACH`, — обычные файлы
  [`.mesh`](mesh.md), находимые через дескриптор инвентарного предмета
  (см. [actor_xml.md](actor_xml.md), блок `<Items>`).
- Текстура кожи — вариант [`.tex`](tex.md).

---

## 5. Оговорка

Поскольку `danko.hand` — **единственный** экземпляр этого формата в
поставочном контенте, описанная выше раскладка байтов частично
экстраполирована из функций загрузчика и из аналогичного загрузчика
костной анимации в
`Game/Renderers/D3D9/GeometryAnimBoneData.cpp`. Порядок полей точно
соответствует вызовам конструктора, но субраскладка ключевого кадра не
перечислена ни в одной вспомогательной структуре — она читается inline.

Если нужны точные байтовые смещения, выполните hex-дамп `danko.hand`
параллельно с `HandsData.cpp:CHandsData::CHandsData` — они соответствуют
1 к 1.
