# `.isc` — определение внутренней сцены (XML)

- **Архив**: `Scenes.vfs` (796 файлов).
- **Примеры**: `sobor_trup.isc`, `sobortrup_base.isc`, `house1_base.isc`,
  `factory_base.isc`.
- **Загрузчик**: `CSceneIndoor::CSceneIndoor(CWorld *, ISceneInterface *,
  ICustomSceneIndoor *, IXMLParser *)` — `Game/Engine/SceneIndoor.cpp:72`.
- **XML-парсер**: `CSimpleXML` (`Game/Engine/SimpleXML.cpp`),
  доступный через интерфейс `IXMLParser`.

---

## 1. Формат: обычный XML

`.isc` — это **текстовый XML**, не бинарный. UTF-8 (совместимый с ASCII)
без явного объявления и BOM. Тело файла на диске передаётся
непосредственно в `IXMLParser::Parse(buffer, size)`.

Небольшой пример, `Scenes.vfs/sobor_trup.isc` (96 байт всего):

```xml
<Scene>
    <Name>sobor</Name>
    <reference filename="sobortrup_base.isc" node="Scene"/>
</Scene>
```

Весь архив заполнен такими крошечными «дельта»-файлами `.isc`, которые
`<reference …/>` ссылаются на более богатый `*_base.isc` и затем
добавляют/переопределяют несколько элементов.

---

## 2. Схема элементов

### 2.1 `<Scene>` (корень)

Единственный корневой элемент. Все остальные элементы появляются как
прямые потомки. Внутренний вариант должен содержать `<Level>` (статический
BSP-меш).

### 2.2 `<reference filename="…" node="…"/>` — наследование XML

`CSimpleXML` разрешает узлы `<reference>`, загружая указанный файл через
тот же `IFileSystem` (`FS_STD_SCENE`) и **встраивая** содержимое
`node="…"` в позицию тега `<reference>`. Это разновидность XInclude
движка.

Именно поэтому `Scenes.vfs/sobor_trup.isc` весит всего 96 байт: он
импортирует `sobortrup_base.isc` и подставляет заголовок.

### 2.3 `<Name>title</Name>`

Отображаемое название сцены (отладочный лог + UI).

### 2.4 `<Ambient>R G B</Ambient>`

Цвет рассеянного света. Три числа с плавающей точкой через пробел;
зажимаются в [0, 1]. По умолчанию (0, 0, 0), если отсутствует.

### 2.5 `<Level>actor_name</Level>`

**Обязательно.** Имя BSP/level-актора (файла размещения в
[Actors.vfs](actor_placement.md)), задающего статические стены, полы и
потолки внутренней сцены.

### 2.6 `<PathFinding DataFile="<name>.pfd"/>`

Необязательно. Ссылается на файл [`.pfd`](pfd.md) в `Scenes.vfs`,
содержащий предвычисленный navmesh.

### 2.7 `<Cache>…</Cache>`

Необязательно. Предзакэшированные списки геометрий/текстур, которые нужно
закрепить в памяти до начала загрузки акторов. См. `CSceneBase::LoadCachedData`
(`SceneBase.cpp`).

### 2.8 `<SceneLocators>…</SceneLocators>`

Именованные точки респавна/спавна, на которые акторы ссылаются через
атрибут `Location="…"`. Каждый потомок — это `<Locator Name="…" Pos="x y z" Dir="x y z"/>`.

### 2.9 `<Group id="N"/>`

Объявляет ID группировки акторов, используемый для массовых операций,
управляемых скриптами (например, «скрыть всех акторов в группе 7»). См.
`CSceneBase::LoadGroups`.

### 2.10 `<Actor …/>` — размещение

Основной элемент внутри сцены. Распознаваемые атрибуты:

| Атрибут       | Тип      | Значение                                                  |
|---------------|----------|-----------------------------------------------------------|
| `Name`        | string   | Имя файла актора (разрешается в `Actors.vfs/<Name>`). Обязательно, если не задан `Type`. |
| `Type`        | string   | Имя типа актора (`fog`, `flame`, `scripted`, `blank`, `scripted_container`, `sound-fake3d`). Используется для программно создаваемых акторов, не имеющих файла на диске. |
| `Extras`      | string   | XML-переопределение экземпляра (разрешается в `Actors.vfs/<Extras>`). См. [actor_xml.md](actor_xml.md). |
| `StaticID`    | u32      | Идентификатор, используемый BSP-мешем уровня для различения совпадающих пропсов. |
| `Location`    | string   | Имя `<Locator>` для спавна. Необязательно. |
| `Group`       | child    | Один или несколько `<Group id="N"/>` потомков связывают актор со скриптовыми группами. |

### 2.11 `<Map FileName="…"/>` — ссылка на UI-карту

Необязательно. Имя битмапа [`.map`](map.md) (в `Scenes.vfs`),
управляющего UI карты мира для этого региона. У внутренних сцен он
встречается редко.

### 2.12 `<Regions FileName="regions.xml"/>` — дескриптор регионов

Только для внешнего мира; см. [osc.md §3.3](osc.md). Внутренние `.isc`
обычно не содержат этого.

## 3. Семантика наследования и переопределения

Когда `<reference>` встраивает содержимое, движок **не дедуплицирует**:
список `<Actor>` базового файла копируется буквально, а любые строки
`<Actor>`, следующие за `<reference>`, просто добавляются к (или
переопределяют внутри `StaticID`) базовому списку. На уровне XML нет
diff/merge — это текстовая конкатенация через парсер.

Таким образом, шаблон такой:

```
project_base.isc  ← всё тяжёлое (BSP, сотни строк акторов)
project.isc       ← крошечная заглушка, наследующая и добавляющая/меняющая несколько пропсов
```

Это сохраняет файл сцены лёгким, позволяя сотням «вариантных» сцен
использовать одну тяжёлую базу.

---

## 4. Сжатие

Нет. Файлы `.isc` — обычный текст.

## 5. Перекрёстные ссылки

- Level-актор в `<Level>…</Level>` — файл размещения без расширения: см.
  [actor_placement.md](actor_placement.md).
- Акторы, на которые ссылается `<Actor Name="…">`, — файлы размещения без
  расширения в `Actors.vfs`; значение `<Actor Extras="…">` — это
  XML-файл [actor_xml.md](actor_xml.md).
- Пара для поиска пути: см. [pfd.md](pfd.md).
- Внешний аналог: см. [osc.md](osc.md). Структурно идентичный XML, за
  исключением того, что `<Land>` заменяет `<Level>`, и появляются
  секции для внешнего мира (`<Regions>`, `<Map>`).
