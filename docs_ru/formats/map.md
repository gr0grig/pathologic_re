# `.map` — растровое изображение карты мира UI

- **Архив**: `Scenes.vfs` (1 файл: `city.map`).
- **Загрузчик**: `CWorldMap::LoadData(IEngine *, const char *pszFileName)` —
  `Game/Game/WorldMap.cpp:680`.
- **Владеющий интерфейс**: `IWorldMap` (`Game/Game/IWorldMap.h`).
- **Ссылка из**: `<Map FileName="city.map"/>` внутри
  [`.osc`](osc.md).

---

## 1. Назначение

`.map` — это **UI карта мира**, которую игрок открывает игровой клавишей
карты. Файл содержит:

- Полигональную **сетку регионов** (чтобы UI мог подсвечивать кварталы
  города — см. `Regions FileName="regions.xml"/>` в
  [world_xml.md](world_xml.md)).
- Имя ссылки на **фоновую текстуру** (отрисованное изображение карты,
  находящееся как [`.tex`](tex.md) в `Textures.vfs`).
- Попиксельную **карту индексов объектов**, чтобы клик по карте определял,
  по какому актору/региону кликнули.
- Таблицу объектов — выбираемые предметы / точки быстрого перемещения.
- Позицию обзора и зум по умолчанию для UI-камеры.

`Scenes.vfs/city.map` — единственный поставочный файл, потому что в
альфе одна внешняя сцена (`city.osc`), а внутренние сцены не используют
UI-карту.

---

## 2. Раскладка на диске

Файл разделён на две области: несжатый **префикс PlaneGrid**, за которым
следует **полезная нагрузка, сжатая zlib**.

```
+----------------------------------------+
| PlaneGrid (uncompressed, var size)     |   см. 2.1
+----------------------------------------+
| u32  uncompressedPayloadSize           |   заголовок CZipReader
| deflate stream                         |   содержимое см. 2.2
+----------------------------------------+
```

### 2.1 PlaneGrid (меш-полигоны регионов)

Создаётся `IFactory::CreatePlaneGrid(const char *pszData)`. Реализация в
`Game/Engine/PlaneGrid.cpp` разбирает поток байтов на месте и продвигает
указатель, мимо которого вызывающая сторона затем перепрыгивает:

```cpp
const char *pszData = reader.GetPointer();
m_pRegions.reset(g_factory->CreatePlaneGrid(pszData));
reader.Skip(pszData - reader.GetPointer());
```

PlaneGrid — это, по сути, 2D-триангуляция, сгруппированная в именованные
**регионы**. Эмпирическая раскладка (проверено на первых 16 байтах
`city.map`: `10 00 00 00 02 00 00 00 08 00 00 00 …`):

```
u32  regionCount       // 0x10 = 16 регионов в city.map
u32  ??                // 0x02 — вероятно, версия или флаги
u32  vertexCount       // 0x08 — начало общего пула вершин
CVector2[vertexCount]  // 8 байт каждая (x, y) в мировых единицах

На регион:
  u32   triangleCount
  TRI[] triangleCount   // каждый треугольник = 3 индекса вершин, возможно u16 или u32
  …
```

Точная субструктура записи на регион инкапсулирована внутри реализации
`CreatePlaneGrid` (`PlaneGrid.cpp` / `PlaneGrid.h`) и не раскрыта в
коде загрузчика выше. Потребителям нужны только:

- `m_pRegions->GetRegionCount()` — число регионов.
- `m_pRegions->GetTriangleCount()` — всего треугольников по всем регионам.
- `m_pRegions->EnumTriangles(ITriangleEnum*)` — итерация callback'ов
  `(NewRegion(i), Triangle(p1, p2, p3) × N)`.

Триангуляция используется **только для hit-теста и подсветки региона**.
Видимый фон карты — отдельная текстура (следующий раздел).

### 2.2 Сжатая полезная нагрузка

После того как `CreatePlaneGrid` сдвигается за блок PlaneGrid, остальное
оборачивается в `CZipReader<CStringReader>` и содержит:

```
u32       m_ulTexWidth        // ширина фоновой текстуры в пикселях
u32       m_ulTexHeight       // высота в пикселях
CEString  textureName         // имя .tex / .png для загрузки
                              // (например, "city_map.tex")
u16[m_ulTexWidth * m_ulTexHeight]  m_pObjMap
                              // попиксельный поиск объекта (0 = нет)
f32       m_vViewPos.x        // центр UI-камеры по умолчанию, в пикселях текстуры
f32       m_vViewPos.y
f32       m_fZoom             // коэффициент зума UI по умолчанию
u32       m_ulObjCount        // число кликаемых объектов
OBJECT_DATA[m_ulObjCount]     // POD фиксированного размера (id, мировая позиция, id подписи…)
```

`m_pObjMap` — наиболее характерное поле: 16-битная сетка того же
размера, что и текстура карты, в которой каждый пиксель несёт индекс
объекта, который был бы выбран при клике игрока в эту точку. Индекс 0 =
«нет объекта». Это сводит весь pick-test к поиску по текстуре за O(1).

`OBJECT_DATA` — упакованная C-структура, читаемая через `ReadArray`,
поэтому это сырой `memcpy`. Её раскладка находится в `WorldMap.h` и
включает (как минимум) мировую позицию, индекс региона и string ID для
подписи объекта (разрешается через `IStringDatabase` — см.
[dat_strings.md](dat_strings.md)).

---

## 3. Сжатие

Ведущий блок PlaneGrid **не** сжат (читается на месте). Полезная нагрузка
начиная с `m_ulTexWidth` **сжата** zlib (`78 DA …`) внутри обёртки
`CZipReader`. См. [README.md §Соглашения](README.md).

---

## 4. Связанные ресурсы

- Текстурированный фон и иконки объектов находятся в
  `Textures.vfs` (обычно `<name>.tex` — см. [tex.md](tex.md)).
- Полигональные регионы символически связываются с
  `World.vfs/regions.xml` (см. [world_xml.md](world_xml.md)), который
  несёт **имена** регионов и **string ID** подписей.
- Карта загружается лениво при первом открытии UI через
  `CUIMapContext` (`Game/Game/UIMapContext.cpp`).

---

## 5. Оговорка

Побайтовая раскладка секции PlaneGrid **частично выведена**, так как
`CreatePlaneGrid` парсит её из `const char *&` и обёрнут в приватный
файл `Game/Engine/PlaneGrid.cpp` — эмпирически проверены только первые
три u32. Добавьте проход hex-дампа над `city.map` параллельно с
`PlaneGrid.cpp`, если нужны точные смещения битов.
