# `.ogg` — аудио Ogg Vorbis

- **Архив**: `Sounds.vfs` (298 файлов).
- **Примеры**: `hit_vozduh_hammer_22.ogg`, `Thunder1.ogg`,
  `mail_received.ogg`, `River.ogg`.
- **Читатель**: `libvorbis` / `libvorbisfile`. Интеграция в движок:
  `Game/Sound/SoundManager.cpp:205` (предзагрузка буферов) и
  `Game/Sound/AsyncStream.cpp:59` (стриминг).
- **Бэкенд воспроизведения**: OpenAL — `alBufferData(...)` в
  `SoundManager.cpp:234` и `Stream.cpp:82, :106`.

---

## 1. Формат

Файлы — **стандартные потоки Ogg Vorbis** (RFC 3533 / RFC 5334). Без
специфичного для движка обрамления, без шифрования, без zlib-обёртки. Их
можно открыть в любом аудиоплеере, поддерживающем Vorbis.

Сигнатура файла: `4F 67 67 53` (`"OggS"`) по смещению 0 — стандартный
заголовок Ogg-потока.

Параметры кодирования, применённые при сборке ассетов:

- **Vorbis I** (единственный профиль Vorbis; дефолт libvorbis).
- **Моно или стерео** — путь воспроизведения ветвится по
  `m_pReader->IsMono()` в `Stream.cpp:82, :106`.
- Переменный битрейт; альфа-файлы ориентированы примерно на 96–128 кбит/с.
- Частота дискретизации различная (`m_pReader->GetRate()` пробрасывается в OpenAL).

---

## 2. Конвейер движка

Существуют **два пути воспроизведения**, выбираемые для каждого звука
атрибутом `stream="0|1"` в XML интерфейса ([ui_xml.md](ui_xml.md)) и флагами
из списка звуков актёра ([actor_xml.md](actor_xml.md), §3.5):

### 2.1 Предзагрузка (одноразовые эффекты)

`CSoundManager::CreateSoundData(...)`
(`Game/Sound/SoundManager.cpp:205`):

```cpp
OggVorbis_File vf;
if (ov_open_callbacks(&ld, &vf, NULL, 0, *m_pOGGCallbacks)) { /* error */ }
// decode entire stream into a contiguous PCM buffer
…
alBufferData(uiBuffer, uiFormat, pSoundData, uiBufferBytes, uiRate);
```

Весь файл декодируется в 16-битный PCM в память при загрузке, затем
загружается в один буфер OpenAL. Лучше всего подходит для коротких SFX
(менее нескольких секунд).

### 2.2 Стриминг (музыка, окружающие лупы, диалоги)

`CAsyncStream` (`Game/Sound/AsyncStream.cpp:59`) открывает OGG через
`ov_open_callbacks`, но **декодирует инкрементально** в кольцо буферов OpenAL
фиксированного размера (обычно четыре буфера, ~ 0.25 с каждый). Фоновый поток
дозаполняет потреблённые буферы через `FillBuffer(...)`
(`oggfile.cpp:57`).

Этот путь используется для:
- Всей музыки (`<sound stream="1" loop="1">…</sound>`).
- Эмбиентов реки / ветра / огня.
- Голосовых реплик диалогов (длинные, одноразовые).
- Кинематографической озвучки.

---

## 3. Обработка лупов

`FillBuffer(void *, unsigned long, bool bLoop, OggVorbis_File &)`
принимает явный флаг `bLoop` (`oggfile.cpp:57`). При его установке
читатель ищет назад к сэмплу 0 при достижении конца потока и продолжает
заполнение — поэтому лупы **точны по сэмплам** (без заметного разрыва, если
аудиоредактор корректно замкнул луп в сэмплах).

Атрибут `loop="0|1"` в XML интерфейса и в списке звуков актёра управляет
этим флагом.

---

## 4. Позиционное 3D-аудио

Бэкенд OpenAL поддерживает HRTF / панорамирование через `alSource3f(AL_POSITION,
…)`. Сторона мира подключает это через:

- `ACTOR_SOUND_FAKE3D` (id 21) — излучает с фиксированной мировой позиции
  ([actor_placement.md](actor_placement.md), [actor_xml.md](actor_xml.md)
  пример `sound_river.xml`).
- `Sound3D.cpp` — универсальный 3D-источник, прикрепляемый к любому актёру.

Позиция слушателя следует за камерой. Параметры затухания по расстоянию
(`reference_distance`, `sound_distance`) берутся из `<Properties>` в
XML-конфиге актёра.

---

## 5. Сжатие

Внутреннее Vorbis (перцептуальное). Никакого дополнительного внешнего сжатия
нет — файлы `.ogg` в `Sounds.vfs` хранятся ровно в том виде, в каком их
выдал кодировщик.
