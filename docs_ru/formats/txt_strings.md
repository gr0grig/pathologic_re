# `.txt` — исходник таблицы строк в UTF-16

- **Архив**: `Strings.vfs` (2 файла: `ui.txt`, `console.txt`).
- **Загрузчик**: `CStringDatabase::LoadStringsFromTextFile(IMMLoadObject *,
  unsigned long ulBaseID)` — `Game/Engine/StringDatabase.cpp:46`.
- **Владеющий интерфейс**: `IStringDatabase`.

---

## 1. Назначение

`.txt` — **человекочитаемая альтернатива** бинарной базе строк
[`main.dat`](dat_strings.md). В альфе поставляется два файла:

- `ui.txt` — интерактивные переопределения для строк UI в разработке.
- `console.txt` — текст, используемый внутриигровой консолью (`~`).

Эти файлы существуют, чтобы дизайнеры могли горячо редактировать небольшие
наборы строк без пересборки `main.dat`. Они используют тот же словарь
`IStringDatabase`, что и бинарный файл; если оба определяют один ID,
побеждает второй загрузчик (зависит от порядка вставки).

---

## 2. Кодировка на диске

- **Кодировка**: UTF-16LE.
- **BOM**: обязательный. Первые два байта — `FF FE`. Загрузчик отклоняет
  файл, если BOM отсутствует или длина в байтах нечётна
  (`StringDatabase.cpp:48-52`):

  ```cpp
  if (pLoad->GetSize() % 2)                  return false;
  if (pszData[0] != '\xFF' || pszData[1] != '\xFE')  return false;
  ```

- **Концы строк**: Windows `\r\n`. Читатель срезает `\r` после обрезки,
  поэтому только `\n` тоже принимается, но даёт слегка более странные
  диагностики.

---

## 3. Грамматика

```
file        ::= preamble '@' body
preamble    ::= ( line '\n' )*              -- ignored (comments / header)
body        ::= ( entry )*
entry       ::= u32-id '\n' { string-line '\n' } '@'
```

Прозой:

1. Всё до **первого `@`** в строке трактуется как отбрасываемая преамбула
   (на практике используется для комментария-копирайта/заголовка).
2. Каждая запись начинается с десятичного целочисленного ID на собственной
   строке.
3. Следующие строки — это тело строки до следующего `@`. Строки
   конкатенируются разделителем `\n`. Завершающий `\n` отбрасывается, затем
   срезаются все символы `\r`.
4. Следующий `@` завершает запись и начинает следующую.

### 3.1 Пример

```
This is a header comment that gets ignored.
It may span multiple lines.
@
100
First UI string.
This is its second line.
@
101
Second UI string (single line).
@
```

После загрузки `IStringDatabase` содержит:

| ID  | Value                                       |
|----:|---------------------------------------------|
| 100 | `First UI string.\nThis is its second line.` |
| 101 | `Second UI string (single line).`           |

## 4. Поведение читателя

```cpp
unsigned long ulSize = pLoad->GetSize() / 2 - 1;
wistringstream sstr(pData.get());
sstr.exceptions(ios::failbit);
// 1. skip preamble (everything before first '@')
// 2. for each entry: read ulID, then accumulate lines until next '@'
// 3. AddString(ulID + ulBaseID, strString);
```

(`StringDatabase.cpp:55-110`)

Любая ошибка чтения бросает исключение, и загрузчик молча возвращает текущее
состояние `bOverwrite` (ловя исключение на границе функции). Это означает,
что некорректный `.txt` загрузится частично — записи до места ошибки
остаются.

`ulBaseID` позволяет вызывающей стороне неймспейсить ID, смещая каждую
запись. Оба поставляемых `.txt`-файла загружаются с `ulBaseID = 0`, поэтому
их идентификаторы делят то же числовое пространство, что и `main.dat`.

## 5. Сжатие

**Отсутствует.** Простой UTF-16LE-текст.

---

## 6. Рабочий процесс редактирования

Два валидных цикла редактирования:

1. **Только bin**: править внешнюю мастер-таблицу → переэкспортировать
   `main.dat` → пересобрать `Strings.vfs` через `pkutil`.
2. **Bin + txt-переопределения**: загрузить `main.dat`, затем загрузить
   `ui.txt`, чтобы наложить правки. Альфа использует это для быстрых
   итераций по UI-строкам в работе.
