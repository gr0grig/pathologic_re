# Система освещения

В отрендеренный кадр вкладываются три категории источников света:

1. **Статический свет** — расставляется на этапе сборки сцены,
   запекается в lightmap'ы там, где геометрия статична.
2. **Динамический свет** — рантайм-источники (фонари, огонь, спавны
   из скриптов), вычисляется per-vertex / per-pixel каждый кадр.
3. **Ambient + небо** — постоянный базовый вклад от элемента
   `<Ambient>` сцены плюс направленное солнце skybox'а.

Интерфейсы (в `SRC/PlagueCity/Engine/Renderer/`):

- `ILight` — базовый источник света.
- `ILightStatic` — запечённый.
- `ILightPoint` — точечный, позиция + цвет + радиус.
- `ILightGroup` — коллекция источников, движущихся вместе.
- `ILightOccluder` — геометрия, **отбрасывающая** тень / блокирующая свет.
- `ILightArray` — view-список того, какие источники влияют на конкретный объект.
- `ILightEnumerator` — visitor-интерфейс.

Обёртки-акторы (в `SRC/PlagueCity/Game/Game/`):

- `CActorLightStatic` (id 1) — актор одного статического источника.
- `CActorLightStaticGroup` (id 2) — группа статических источников,
  запекаемых вместе.
- `CLightPoint` (`LightPoint.cpp`) — примитив динамического точечного
  света, прикрепляемый к скриптовым акторам (факелы, фонари, взрывы).
- Система короны-overlay'ев: `CCoronaStandard`, `CoronaList.cpp`.

---

## 1. Статический свет — запечённый

Актор статического света (id 1) — это noext placement-файл в
`Actors.vfs`, тело которого содержит:

```
u32 ulActorID = 1
CVector m_vPosition
COLORVALUE m_cvColor              (R, G, B как 3 float'а)
f32 m_fRadius                     (линейная дистанция затухания)
f32 m_fIntensity                  (по умолчанию 1.0)
... (ID группы света, флаги occluder и т.д.)
```

(Точная раскладка — из `CActorLightStatic::CActorLightStatic` в
`ActorLightStatic.cpp`.)

В рантайме эти источники не пересчитываются: их вклад **запекается в
текстуры lightmap'ов** ассет-кукером (`tools/tile` для terrain'а,
редакторский запекатель для статических мешей — см.
[toolchain.md](toolchain.md)). Lightmap затем семплируется техниками,
имя которых заканчивается на `Maps` (`CTechniqueDiffuseMaps`,
`CTechniqueDiffuseBumpMaps` и т.д. — см.
[render_techniques.md](render_techniques.md) §1).

---

## 2. Группы статических источников

`CActorLightStaticGroup` (id 2) собирает несколько статических
источников, которые редактор хочет рассматривать как одну сущность
(например, все люстры в комнате или все уличные фонари на одном
квартале). У группы есть свой переключатель позиции/видимости;
переключение её on/off в рантайме приводит к смене канала lightmap'а
(шейдеры геометрии семплируют один из двух lightmap'ов: «включён» и
«выключен»).

Модель шейдинга трактует каждую `CActorLightStaticGroup` как
фиксированную пару запечённых страниц lightmap'а. Скрипты могут
звать `Enable(bool)` у группы, чтобы переключаться между ними.

---

## 3. Динамические точечные источники — рантайм

`CLightPoint` — реализация рантайм-точечного источника. Создаётся
скриптовыми акторами (например, скрипт актора-факела вызывает
`@CreatePointLight(self(), colour, radius)` при инициализации).

Данные на один источник:

```
CVector  position
COLORVALUE colour
f32      radius        (cutoff линейного затухания)
f32      brightness    (множитель)
bool     bShadows      (отбрасывает ли источник динамические тени)
```

Динамические источники вычисляются per-vertex для статической
геометрии (через семейство `CTechniqueDiffuseS*` — diffuse + specular)
и per-pixel для анимированных костных мешей (`CTechniqueBoneDiffuse`
— см. [render_techniques.md](render_techniques.md)). На один
draw-вызов попадает не более фиксированного числа динамических
источников (обычно 4), выбираемых через
`ILightArray::SelectClosest(...)` и отправляемых в шейдер как
константные регистры.

---

## 4. Light-массивы и culling

Каждый актор поддерживает `ILightArray *` — список динамических
источников, которые **могут** на него влиять (вычисляется каждый
кадр исходя из мировой позиции и радиусов источников). Рендерер
опрашивает этот массив для каждого актора и берёт top-N ближайших
для реального draw. Источники вне view-объёма актора отсекаются
заранее на уровне сцены.

Статические источники полностью обходят этот массив — их вклад уже
лежит в lightmap'е.

---

## 5. Light-occluder'ы

`ILightOccluder` — это геометрия, **блокирующая** динамический свет.
Включается на акторе передачей `bDynamicShadows = true` (см. тело
статического актора в
[`formats/actor_placement.md`](formats/actor_placement.md) §3.1).
Рендерер проецирует теневую геометрию от каждого динамического
источника через каждый occluder; результат — стенсильная маска,
смешиваемая с освещённой поверхностью.

В этой сборке нет полноценного shadow-map пайплайна — тени
проецируются через стенсил. Если позволяет производительность,
движок рендерит один теневой проход на каждый динамический
источник на каждый occluder.

## 6. Система корон

`CCoronaStandard` (`CoronaStandard.cpp`) рисует 2D-биллборд
**bloom-подобного свечения** вокруг ярких источников света. Каждый
`CActorLightStatic` и каждый `CLightPoint` может объявить текстуру
короны; пайплайн корон:

1. Берёт screen-space позицию каждого источника.
2. Проверяет видимость через depth-буфер через raytest.
3. Рисует текстуру короны аддитивно в проецируемой позиции,
   модулируя её долей пикселей, прошедших тест видимости.

Результат — «ореол свечения» вокруг фонарей, когда вы смотрите
прямо на них.

## 7. Ambient и небо

Элемент `<Ambient>R G B</Ambient>` сцены в
[`formats/isc.md`](formats/isc.md) / [`formats/osc.md`](formats/osc.md)
задаёт плоский ambient-член по каналам, добавляемый к каждому
пикселю сцены.

У уличных сцен дополнительно есть **небо** (`CRenderer::CreateSkyBox`),
дающее сильный направленный **солнечный** свет. Направление и цвет
солнца определяются значениями **времени суток**, хранящимися на
`CGameWorld` (`m_fTimeDawn` / `m_fTimeSunset` / `m_fAngleDawn` /
`m_fAngleSunset` — см. [save_format.md](save_format.md) §6).

Погода (дождь, туман) модулирует эти глобальные параметры — см.
`Game/Game/ModWeatherData*.cpp`.
