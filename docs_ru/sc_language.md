# `.sc` — исходный язык PathologicScript

Оригинальный C-подобный скриптовый язык, потребляемый
[`scomp`](toolchain.md) и эмитируемый в виде байткода `.bin`,
который исполняет рантайм-VM ([bin_format.md](bin_format.md),
[vm.md](vm.md), [opcodes.md](opcodes.md)).

Образцы исходников поставляются в
`SRC/PlagueCity/Game/script_sources/` — и `.sc` (топ-уровневые файлы,
компилируемые в `.bin`), и `.sci` (include-only заголовки).
Стандартная библиотека — в `std.sci`.

---

## 1. Расширения файлов

| Расширение | Роль                                              |
|-----------|---------------------------------------------------|
| `.sc`     | Топ-уровневый исходник. Компилируется в один `.bin`. |
| `.sci`    | Include-only заголовок. Самостоятельно не компилируется. |

`scomp` разрешает `include foo.sci`, ища по include-пути (`-d`),
переданному в командной строке. Флаги компилятора — см.
[toolchain.md §3](toolchain.md).

---

## 2. Топ-уровневые конструкции

Файл `.sc` — последовательность топ-уровневых объявлений:

| Конструкция          | Назначение                                                                                    |
|--------------------|-----------------------------------------------------------------------------------------------|
| `include path`     | Подтягивает другой `.sci` (без кавычек, без точки с запятой — см. std.sci:1).                |
| `event NAME ID;`   | Объявляет канал события (например, `event OnUse 0;`). Числовой ID — порядковый номер события. |
| `const T NAME = …;`| Константа файлового scope (типизированная). `const float PI = 3.1415926535897932;`            |
| `task NAME { … }`  | *Вызываемая* задача. Re-entrant; может быть запущена через `RunTask`.                         |
| `maintask NAME : BASE { … }` | Точка входа скрипта. Наследуется от `BASE` (тоже `task` или `maintask`).            |
| `T func(args) { … }` | Свободная функция, возвращающая тип `T`.                                                    |

Минимальный пример `.sc`:

```c
include std.sci
include actor_item_base.sci

maintask TInventoryObject : TActorItem
{
}
```

`maintask` здесь неявный: у него нет собственного тела, и он
получает всё из базы `TActorItem`. Компилятор эмитит опкод
`RunTask`, который запускает его при загрузке скрипта.

## 3. Типы

Встроенные скалярные / значимые типы:

| Тип       | Примечания                                                         |
|-----------|--------------------------------------------------------------------|
| `int`     | 32-битный знаковый.                                                |
| `float`   | 32-битный IEEE 754.                                                |
| `bool`    | 1 байт. `true` / `false`.                                          |
| `string`  | Переменной длины, immutable. Хранится как UTF-16 в строковом пуле VM. |
| `Vector`  | 3 × `float`. Конструируется литералом `[x, y, z]`.                |
| `object`  | Непрозрачная ссылка на сущность стороны хоста (актор, сцена, геометрия, set, vector). |

**Ни массивов, ни структур в пользовательском коде нет.** Sets и
vectors объектов существуют как host-managed типы, создаваемые через
`CreateObjectSet()` / `CreateObjectVector()`.

### 3.1 Литералы и операторы `Vector`

```c
Vector v = [1, 2, 3];        // литерал
Vector d = v2 - v1;          // покомпонентное вычитание
float dot = v1 | v2;         // скалярное произведение
Vector cross = v1 ^ v2;      // векторное произведение
```

`|` и `^` — операторы языка для `Vector`. Для `int` / `float` они
не работают.

### 3.2 Доступ к членам

`Vector` экспонирует `.x`, `.y`, `.z`. Примеры из `std.sci:191`:

```c
float Dot2D(Vector v1, Vector v2) {
    return v1.x * v2.x + v1.z * v2.z;
}
```

У `object` нет доступных пользователю членов — вызовы идут через
синтаксис методов (см. §6.2).

## 4. Операторы

Стандартные C-подобные:

- Объявления: `int x;`, `float f = 0.5;`.
- Присваивание: `x = 1;`, `+=`, `-=`, `*=`, `/=`, `%=`.
- Составной: `{ … }`.
- `if (cond) … else …`.
- `while (cond) …`, `do … while (cond);`, `for (init; cond; step) …`.
- `return [value];`.
- `break;`, `continue;`.
- Тернарный `cond ? a : b` (часто используется — см. `std.sci:95`).

**`goto` нет**, нет `switch` (решение оригинальной команды),
исключений тоже нет.

### 4.1 Бесконечный цикл (идиома)

Канонический «ждать вечно, пока не придут события» цикл:

```c
for (;;) {
    @Hold();
}
```

`@Hold()` бесконечно отдаёт управление задачей; события её
возобновляют. Модель кооперативного планирования — см.
[tasks.md](tasks.md).

## 5. Определения функций

```c
int min_of(int v1, int v2, int v3) {
    if (v1 < v2)
        return (v1 < v3)? 0 : 2;
    return (v2 < v3)? 1 : 2;
}
```

- Возвращаемый тип объявляется первым; `void` разрешён.
- Параметры — позиционные, по значению.
- **Перегрузка** разрешена по типам параметров (см. `std.sci:151` —
  `rndbool(float)` против `rndbool(int, int)`).
- **Аргументов по умолчанию нет.**
- Рекурсия разрешена.

### 5.1 Out-параметры через host-вызовы

Поскольку host-вызовы не могут вернуть `Vector` или `object` напрямую
в байткоде, по соглашению используется такая форма:

```c
Vector v;
@FindGeometryCenter("door", v);   // хост заполняет v
```

`v` передаётся по ссылке, потому что появляется в списке аргументов
без инициализации — компилятор эмитит указатель на локальную
переменную.

## 6. Соглашения о вызовах

### 6.1 Локальный вызов функции

```c
float d = VectorDist(v1, v2);
```

Эмитит цепочку опкодов `Func` / `Call`.

### 6.2 Host-вызов (`@name`)

Лидирующий `@` обозначает **host-side built-in**. Компилятор эмитит
опкод `Call+` с внешним function ID. Это единственный способ
общаться с движком.

```c
@SetUsable(true, 50);
@FindGeometry("object", geo);
@PlaySound(self(), "hit");
```

Каталог host-вызовов — см. [script_api.md](script_api.md).

### 6.3 Вызов метода (`obj->name(...)`)

```c
geo->Enable(true);
scene->GetLocator(name, bFound, vPos);
```

Методы диспатчатся виртуально через таблицу host-класса объекта.
Эквивалентно `@<ClassName>::name(obj, args…)` после компиляции.

### 6.4 `self()`

Актор, владеющий текущей задачей. Определён в `std.sci:53`:

```c
object self(void) {
    object obj;
    @self(obj);
    return obj;
}
```

## 7. Задачи и `maintask`

`task` — это корутина. Задачи можно запускать через `@RunTask(…)`,
приостанавливать через `@Hold()`, и они получают **события** через
объявления `event`.

`maintask` — **единственная** точка входа в `.sc`. Ровно одна на
скомпилированный `.bin`. Рантайм вызывает её метод `init()` при
загрузке.

```c
maintask TInventoryObject : TActorItem
{
}
```

Наследование **одиночное** (одна база `task` или `maintask`);
производный класс может добавлять новые обработчики событий и
перегружать методы. Ключевого слова виртуального диспатча нет —
override'ы происходят по имени.

Полная модель задач — в [tasks.md](tasks.md).

---

## 8. Обработчики событий

Объявление `event` регистрирует числовой порядковый номер:

```c
event OnUse 0;
```

Внутри `task` можно определить метод с тем же именем; рантайм
вызывает его, когда хост возбуждает соответствующее событие для
актора, владеющего задачей.

```c
void OnUse(object actor) {
    if (!IsAccessible(actor)) return;
    object item;
    @GetItem(item, 0);
    ...
}
```

События подробно задокументированы в
[events_2005.md](events_2005.md). Базовые ID (из `std.sci:5-41`)
покрывают жизненные циклы use / sense / load / timer / attack /
damage / inventory / dispose.

---

## 9. Свойства (переменные на акторе)

`@GetProperty(name, out)` / `@SetProperty(name, value)` обращаются
к свойствам актора, объявленным в XML-блоке `<Properties>` (см.
[`formats/actor_xml.md`](formats/actor_xml.md) §3.3). В скрипте нет
объявления свойства на этапе компиляции — имена разрешаются
динамически в рантайме.

```c
int iCount;
@GetProperty("ammo_count", iCount);
@SetProperty("ammo_count", iCount - 1);
```

## 10. Стандартная библиотека (`std.sci`)

Примерно 250 строк переиспользуемых хелперов. Категории:

- **Базовые события**: `OnUse`, `OnSee`, `OnAttacked`, `OnDeath`,
  `OnDispose`, `OnInventoryAddItem` и т.д.
- **Математика**: `min_of`, `max_of`, `clampf`, `signf`, `betweenf`,
  `SolveQuadraticMinPos`, `Normalize`.
- **Хелперы вектора**: `VectorDist`, `Dot2D`, `Length2D`,
  `CosAngle`, `CosAngle2D`.
- **RNG**: `rndbool(prob)`, `rndbool(num, denom)`.
- **Строки**: `strchr`, `strsub`.
- **Глобалы**: `GetVariable`, `IncVariable`, `DecVariable`,
  `SetVariable` — обёртки над host-вызовами `@GetVariable` /
  `@SetVariable`.
- **Локаторы сцены**: `GetLocatorPosition(scene, name)`.

Всегда ставьте `include std.sci` первой строкой; большинство других
`.sci`-файлов уже включают её транзитивно.

## 11. Особенности компиляции

- Комментарии: `// строка` и `/* блок */` (без вложенности).
- Препроцессор: поддерживается только `include`; нет `#define`,
  нет `#if`. Вместо этого константы — синтаксис `const`.
- Строковые литералы: `"…"` — распознаются `\"`, `\\`, `\n`, `\t`.
- Числовые литералы: десятичный `int` (`-123`), hex `0x…`, `float`
  с десятичной точкой (`3.14`) или экспонентой (`1e-5`).

Правила идентификаторов:
- Буквенно-цифровые символы + подчёркивание; начинается с буквы или
  подчёркивания.
- Регистрозависимые.
- Локальные переменные и параметры живут в кадре стека отдельной
  задачи.

---

## 12. Во что это компилируется

`scomp` опускает тело каждой функции в поток опкодов стековой VM
([opcodes.md](opcodes.md)), конструируя:

- **строковый пул** (UTF-16 для литералов, ASCII для имён
  host-вызовов),
- **таблицу функций** (имя → смещение в байткоде),
- **буфер байткода** (поток инструкций),
- опциональную **debug-инфу** (таблица файла/строки источника).

Полная раскладка файла — в [bin_format.md](bin_format.md).
Round-trip декомпилятор `decompile.py` восстанавливает C-подобную
форму; она приближённая, не lossless (у этого языка нет
канонической сериализации AST, поэтому некоторые round-trip
`.sc → .bin → .sc` оказываются слегка переупорядоченными).
