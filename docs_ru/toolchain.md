# Тулчейн сборки ассетов

Дерево исходников Pathologic 2005 поставляет **шесть консольных
инструментов**, которые вместе превращают сырой вывод редактора в
архивы `.vfs`, загружаемые движком. Все находятся под
`SRC/PlagueCity/tools/` и линкуются с теми же вспомогательными
библиотеками движка, что и рантайм.

| Инструмент   | Исходник                      | Роль                                                            |
|--------------|-------------------------------|------------------------------------------------------------------|
| `smake.exe`  | `tools/smake/smake.cpp`       | Оркестратор сборки верхнего уровня (читает `.smk`-задания, подобные Makefile) |
| `pkutil.exe` | `tools/pkutil/pkutil.cpp`     | Упаковщик / листер VFS-архивов                                   |
| `scomp.exe`  | `tools/scomp/scomp.cpp`       | Компилятор PathologicScript (`.sc` → `.bin`)                     |
| `sbuild.exe` | `tools/sbuild/sbuild.cpp`     | Вычислитель сборочных скриптов / переменных (используется внутри smake) |
| `gdpconv.exe`| `tools/gdpconv/gdpconv.cpp`   | Конвертер геометрии (`.gdp` редактора → `.mesh` рантайма)        |
| `tile.exe`   | `tools/tile/`                 | Сборщик ландшафта / набора тайлов (запекание лайтмапов, разбиение мешей) |
| `FontGen.exe`| `tools/FontGen/`              | Генератор битмап-шрифтов (TTF → `.ft`)                           |
| `FontGenNew/`| `tools/FontGenNew/`           | Более новая C#/CLR-перереализация FontGen (тот же выходной формат) |

Два вспомогательных инструмента (используются при сборке, не входят в
список) лежат рядом:
- `LemonParser.exe` — заранее собранный бинарь генератора LALR-парсеров Lemon
  (компилирует `parser.y` в таблицу парсера для `sbuild` и `scomp`).
- `lempar.c` — шаблон парсера Lemon.

---

## 1. `smake` — оркестратор верхнего уровня

Миниатюрный клон `make`. Читает XML-подобный «smakefile», который
перечисляет исходные файлы, целевые архивы и инструмент для запуска на
каждом. Конвейер ассетов из `make/pak.xml` обрабатывается `smake`, чтобы
собрать все VFS-архивы за один проход.

### Командная строка

```
smake <smakefile>
```

### Выход

Для каждой известной цели запускает указанный инструмент с указанными
аргументами и пишет вывод в настроенное расположение. Отслеживает
временные метки файлов, пропуская актуальные цели.

Ключевые вспомогательные файлы:
- `tools/smake/MakeList.cpp` — построитель графа зависимостей.
- `tools/smake/SimpleXML.cpp` — XML-парсер (тот же, что используется в
  игре; разделяется копированием).
- `tools/smake/D3DXInclude.cpp` — обрабатывает разрешение `#include`
  для сборок HLSL-шейдеров.

## 2. `pkutil` — упаковщик VFS

Полностью документирован в [vfs_format.md §6](vfs_format.md). Кратко:

```
pkutil c <archive.vfs> <source_dir> [pattern]   # create, strict name check
pkutil f <archive.vfs> <source_dir> [pattern]   # create, force (warn on bad names)
pkutil l <archive.vfs>                          # list contents
```

Исходные файлы в `tools/pkutil/`:
- `pkutil.cpp` — диспетчеризация CLI.
- `PakFile.cpp` / `PakDirectory.cpp` — построитель + писатель дерева каталогов.
  Точно отражают ожидания рантайм-читателя
  ([vfs_format.md](vfs_format.md)).

Управляется `make/pak.xml` для 10 архивов, поставляемых с alpha
(Actors, Fonts, Geometries, …).

---

## 3. `scomp` — компилятор скриптов

Компилирует исходники PathologicScript (`.sc`) в байт-код `.bin`,
запускаемый VM движка. Детали языка — в
[sc_language.md](sc_language.md); раскладка результирующего `.bin` — в
[bin_format.md](bin_format.md).

### Командная строка

```
scomp <source.sc> [-o <out.bin>] [-d <include_dir>]…
```

### Конвейер

```
.sc → preprocessor (#include) → lexer → Lemon-generated parser → AST
    → semantic analysis (declarations, types, scopes)
    → bytecode emitter → .bin
```

Исходные файлы в `tools/scomp/`:
- `scomp.cpp` — CLI-драйвер.
- `BuildInclude.cpp` — разрешение пути `#include`.
- `parser.y` (в `sbuild/`, разделяемый) — Lemon-грамматика
  языка.

Дерево исходников компилятора довольно небольшое (~1500 строк) — основная
семантика языка живёт в рантайм-VM, а не в компиляторе.

---

## 4. `sbuild` — вычислитель сборочных скриптов

Препроцессор общего назначения и вычислитель выражений, используемый
другими инструментами, когда им нужны настраиваемые правила сборки.
У него есть собственный небольшой язык с переменными, условиями и
арифметикой; Lemon-грамматика лежит в `tools/sbuild/parser.y`.

Компоненты:
- `sbuild.cpp` — CLI.
- `Program.cpp` — интерпретаторный цикл верхнего уровня.
- `Expression.cpp` — вычислитель узлов выражений.
- `Variables.cpp` — подстановка `$name`.
- `IOperator.cpp` — встроенные операторы (`+`, `==`, конкатенация строк).
- `DataPool.cpp` — интернирование строк + таблица символов.

Используется как внутри `scomp` (для вычисления `#if`-выражений во
время препроцессинга), так и в качестве отдельного инструмента в
`pak.xml` для построения списков файлов.

## 5. `gdpconv` — конвертер геометрии

Читает файлы `.gdp`, создаваемые редактором уровней (`GameEditor/`),
и эмитит файлы `.mesh` движка. Формат `.gdp` — это
**редакторное** представление (с редакторными метаданными: группы,
именованные материалы, плоскости привязки, UV для лайтмапов);
`gdpconv` убирает редакторные данные, упаковывает буферы вершин/индексов,
вычисляет ограничивающий бокс и радиус и выдаёт формат, описанный в
[`formats/mesh.md`](formats/mesh.md).

### Командная строка

```
gdpconv <source.gdp> <output.mesh>
```

Ключевой файл:
- `gdpconv/gdpconv.cpp` — основная процедура конвертации.
- `gdpconv/FakeD3D.cpp` — предоставляет заглушку D3D-устройства, чтобы
  D3DX-преобразования геометрии работали без настоящего GPU.

Для анимированных мешей (`.mms`) есть отдельный путь (не в
`gdpconv` — см. цепочку плагина LifeStudio HEAD), который выдаёт
обёрнутый zlib блоб скелета+ключевых кадров, описанный в
[animation.md](animation.md).

## 6. `tile` — построитель ландшафта / тайлов

Обрабатывает чанковый уличный ландшафт (актор «Land» города). Принимает
heightmap + набор текстурных тайлов и выдаёт:
- Статический меш `Land`.
- 2D BSP / сетку для коллизий по каждому тайлу.
- Лайтмап-текстуры через офлайновое запекание shadowmap'ов.

Авторы контента не вызывают его часто после того, как сам город уже
запечён — но исходник поставляется для воспроизводимости.

---

## 7. `FontGen` / `FontGenNew` — генератор битмап-шрифтов

Принимает системный TrueType-шрифт (через FreeType) и рендерит каждый
нужный глиф в упакованный `.ft`-файл (см.
[`formats/ft.md`](formats/ft.md)).

- `FontGen/` — исходная MFC/Win32-GUI-версия (`FontGen.cpp`,
  `FontDataBase.cpp`, `FontRendererFT.cpp`).
- `FontGenNew/` — более новая C# / CLR-перереализация (`FontGenCore/FontFace.cpp`).
  Тот же выход бит-в-бит.

## 8. Типичный сквозной поток

```
GameEditor → .gdp / .lsh / .png / .sc → smake (runs:)
   ├ gdpconv  ──→ .mesh
   ├ scomp    ──→ .bin
   ├ FontGen  ──→ .ft
   ├ tile     ──→ land/.mesh + lightmaps
   └ ...
… plus copies of .png/.tga/.tex/.ogg ...
       │
       ▼
   pkutil c → Actors.vfs / Geometries.vfs / Scripts.vfs / Sounds.vfs /
              Textures.vfs / Fonts.vfs / Scenes.vfs / Strings.vfs /
              UI.vfs / World.vfs
       │
       ▼
   alpha/data/*.vfs  →  ready to ship
```

`make/pak.xml` оркестрирует, какой промежуточный файл попадает в какой
архив — этот файл является **источником истины** для таксономии
ассетов, которую [`formats/README.md`](formats/README.md) документирует
со стороны рантайма.

---

## 9. Предварительные требования сборки

Все инструменты статически линкуют вспомогательные библиотеки движка
(STLport, boost, инфраструктуру кастомного аллокатора). Цель — Windows
**x86-32 только**; сборка под современными 64-битными тулчейнами
требует портирования STLport.

Каталог `Intel.CPP.Compiler.v7.1/` под `SRC/` содержит точный
компилятор, использовавшийся оригинальной командой. Visual C++ 2005 (8.0)
также совместим.
